# ARCHITECTURE-SPINE Final Brownfield Reality Review v4

## Verdict

**FAIL。** 四个 normative artifact 的 raw SHA-256 与 Spine/Registry 固定值一致，三个 JSON 文件语法有效，20 个 registry schema pointer 均可解析。v4 已实质补上 `## Project Status`、`delivery-record.state.json`、五类 WDR writer、typed receipts、journal commit point、structured dependency profiles 与 POSIX/Windows adapter；但以下五组 High 仍阻断现有 brownfield 实现确定性迁移。

## Remaining High Findings

- **High：`wdrCreateV1` 与 owned-section wire shape 无法唯一复现现有 WDR。** `wdrOwnedSectionMutation.lines` 的每一项都引用非空 `canonicalSingleLine`（schema `:150-159`），因此不能表达现有 template 各 section 中必需的空行、表格间隔和段落分隔（`skills/adp-workstream-register/assets/workstream-templates/delivery-record.md:5-67`）。create command 又只携带七个 owned sections 和一个未绑定 artifact/hash 的 `template_version`（schema `:194-208`）；它不能表达 H1、`Created`、`Project Status` 的初始 labels/values，也没有规范这些 bytes 由 engine 自动合成。Protocol `2.21` 只固定 section 顺序，没有固定 preamble、默认 Project Status bytes 或 template fingerprint。两个 conforming engine 因而可能生成不同 WDR，甚至没有任何 schema-valid command 能生成当前 template。必须允许显式 blank lines，并 pin 完整 create renderer/template bytes、默认 Project Status、preamble 与 exact section multiplicity/order；加入 byte-exact create vector。

- **High：真实 physical writer surface 仍超出 writer inventory 和 command 能力，owner matrix 也不可验证。** 现有 status-sync 除 current fields/Next actions外还写 `Last status sync`（`sync_status.py:25-35`）和整个 `## Roadmap` milestone table（`:1285-1366`），但 `wdrPatchV1.set` 没有 `last_status_sync`，owned-section enum也没有 `roadmap`（schema `:150-188`）；`status`/`phase` 属于现有 `Identity` labels，Protocol却未固定这两个 patch fields到 heading/label 的 renderer映射。risk review实际修改 `Blockers`、`Risks`、`Scope or change notes`或 `decisions.md`（`review_risk_dependency_change.py:48-53,792-817,849-904`），而 Spine/Protocol inventory声称它写 `Risks/Dependencies/Cross-Workstream Links`。checkpoint当前还把 free-text next action/milestone直接写入 `Next actions`（`sync_bmm_checkpoint.py:994-1002`）。此外 command没有可信 writer identity；owned-section `owner` 是调用者自报，current-field patch甚至没有 owner，engine无法执行声明的 writer/field matrix。必须冻结逐 workflow 的 current/owned/legacy-Roadmap迁移映射，并让调用 principal/producer成为受验证 envelope 或 engine capability，而不是自报字段。

- **High：legacy adapter 仍不能从现有 v1 payload 确定性构造 v2。** Registry只固定 presence、command-ID算法、shared-lock revision和少数错误码（registry `:183-205`），未 pin 两个 v1 source schema/hash或逐字段转换。现有 meeting intake使用嵌套 `updates[].actions[]`、`due`、`workstream`、`id` 等字段（`sync_meeting.py:1371-1445`），status decoder还把 action `id` 当成 `action_id`，并接受 `due|trigger|due_or_trigger`等 aliases（`sync_status.py:393-429,529-588`）；不同 adapter可对 raw presence、alias precedence、defaults和 create/patch 得出不同结果。更直接地，v2 evidence强制 `observed_at`（schema `:61-70`），Protocol `1.11` 只说从 intake raw bytes生成 evidence，没有规定无 canonical timestamp 的 status payload如何确定该值；使用 mtime或当前时间都会破坏 replay identity。必须发布 closed v1 ingress schemas和字段映射/alias precedence，并固定 evidence timestamp/source fragment derivation及对应 golden vectors。

- **High：journal runtime wire truth 与 Windows apply 边界仍不可实现。** Protocol固定了 `root-registry.json`、`fact-generation.json`、`panel-state.json`、`current-pointer.json`、journal manifest/markers和nonce index路径（Protocol `8.59`），但 schema/registry没有这些 durable state 的 shape、初值、identity或升级 contract；实现无法预先计算 generation/pointer target bytes和 hashes，违反 AD-11。Windows adapter只指定 `ReplaceFileW`（Protocol `8.60`），该 API要求目标已存在，不能提交首次创建的 WDR、state sidecar、receipt或generation file；协议缺 atomic create/no-replace primitive。路径也直接嵌入 `<projection-id>`/`<transaction-id>`，而 projection ID是 `sha256:<hex>`、legacy command ID是 `legacy:<hex>`且 `commandId`允许冒号（schema `:26-29,309-318`），这些名称在 Windows非法。必须为全部 runtime files注册 schema，定义 bootstrap bytes，并增加 Windows atomic-create primitive和 filesystem-safe ID encoding；conformance vectors必须覆盖 absent target和非法 filename。

- **High：registry dependency profiles仍不等于现有 producer read set，且非 WDR fact writers未纳入 publication fence。** DAG把 `action-flow`、`risk-flow`列为flow-graph direct upstream（registry `:214-230`），却没有两者的 input profile，orchestrator无法按registry生成或验证它们。roadmap实际读取 checkpoint candidates、business decision packets、locale catalog、audit/prepass和baseline history（`render_roadmap.py:380-405,777-781,1177,1515,1701-1705,1937`），其 profile只枚举 baseline/WDR/decision/readiness（registry `:307-319`）。meeting-pack还直接读取 action ledger、decision log、locale/config和多类 receipts（`render_meeting_pack.py:863-922,1374,1422-1424,1835-1854`），profile `:337-354`未覆盖；management-panel profile的 leaf sources为空（`:356-370`），现实现却读取 artifact audits、program snapshots、meeting receipts和renderer assets（`management_panel.py:334-389,531-589,986-989`）。反向地，state-audit的 `existing-view` glob枚举整个 `views/**/*.json`（registry `:282-283`），会把自身/同代 outputs和未实际消费文件变成 leaf，制造自依赖并违反 exact-consumed receipt。checkpoint、meeting和risk workflows仍直接写 daily/evidence/decision/readiness等被这些 profiles读取的 facts，却未被 AD-10/receipt writers纳入 shared lock、journal和 `fact_generation`；final fingerprint check持锁时它们仍可并发写，TOCTOU fence不成立。必须先用 instrumentation冻结每个 producer真实 read inventory，补齐 action/risk-flow profiles，区分 direct leaf与upstream，排除 output/lineage runtime目录，并把所有会影响 projection 的 fact writer迁入同一 mutation lock/generation协议。
